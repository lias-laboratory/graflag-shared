# e2e_probe — a pipeline fixture, not a method

This is not a graph anomaly detection method and it is not part of the
benchmark. It is the smallest thing that exercises the whole path — build,
push, service, `graflag_runner`, `results.json`, `graflag evaluate` — so that
when a real method fails on the cluster there is a known-good run to compare
against.

It lives under `tests/` rather than `methods/` on purpose. `graflag list
methods` is the catalogue of what GraFlag can benchmark; a probe with a
`SOURCE_CODE` of `https://example.invalid/e2e` listed beside seventeen PyGOD
detectors reads as a method that nobody has finished. For a while it existed
only on the manager, in `/shared/methods/`, which is how the catalogue came to
report twenty-eight entries for a repository holding twenty-seven.

## Running it

It has to be under `methods/` on the share to be runnable, so deploying it is
an explicit act:

    graflag copy -s ./tests/e2e_probe --dest methods -r
    graflag run -m e2e_probe -d e2e_data --build

and removing it again is one command:

    ssh <manager> rm -rf /shared/methods/e2e_probe

`e2e_data` is generated by the probe's own dataset stub; any `.npz` with a
`labels` array works.

## What it deliberately does wrong

The probe's value is in the awkward cases, which a well-behaved method would
never produce and which the pipeline therefore has to be tested against:

- `_MODE=crash` raises; `_MODE=silent` exits 0 **without** writing a result;
  `_MODE=slow` runs for forty seconds. The runner must record `failed` for the
  first two -- exit code 0 is not proof of success -- and must follow the logs
  of the third.
- `_USE_MEMORY=` is an empty value, which `--pass-env-args` has to render as a
  bare `--use_memory` flag rather than `--use_memory ''`.
- `_HIDDEN_DIMS=64 128` contains a space, so it must survive as one argument.
- The script writes a non-UTF-8 byte to stdout, which the log capture has to
  carry through to `method_output.txt` without dying on it.
- `save_scores` is handed a numpy array for `node_ids`, which `ResultWriter`
  has to coerce rather than fail to serialize -- the failure that used to
  leave a truncated `results.json` that still counted as a result.
